# Ink & Ledger — Final Review Checklist

**Purpose.** Use this checklist to review the complete Expense Tracker before publishing. It is organised around the way a person manages money: begin with navigation and entries, review records and analysis, then verify planning and settings. The last section contains the few checks that require a published app or an explicit decision from you.

> **Important:** Verification and password-recovery emails are never sent automatically. Do not select either email action unless you deliberately want to receive that message.

## 1. Review setup

Sign in with the account you intend to use and keep one ordinary test amount ready, such as `10.00`. Use a temporary title such as “Final review entry” so it can be easily found and removed. For each item below, mark **Pass**, **Issue**, or **Not applicable**. When reporting an issue, include the device, browser, screen, exact action, and a screenshot if possible.

| Check | Expected result | Result |
|---|---|---|
| Open the app on a phone-sized screen | The bottom navigation is legible, the central add action is easy to reach, and no text or cards overlap. | ☐ Pass ☐ Issue ☐ N/A |
| Open the app on a desktop-sized screen | The editorial rail, Overview header, and main ledger surfaces remain balanced and usable. | ☐ Pass ☐ Issue ☐ N/A |
| Move through Overview, History, Insights, Goals & Plans, and Settings | Every destination opens predictably and every nested workspace offers a clear route back. | ☐ Pass ☐ Issue ☐ N/A |

## 2. Overview and daily ledger

The Overview should make daily information visible without making the ledger feel crowded. Start here after adding or changing any entry so you can check that totals, pending states, and expected money reflect the change.

| Check | Expected result | Result |
|---|---|---|
| Review Available Balance, Net Worth, inflow, outflow, and savings rate | Values are readable, use the selected currency, and change consistently after a transaction is saved. | ☐ Pass ☐ Issue ☐ N/A |
| Use search and the movement/category filters | The Recent Ledger updates immediately and does not lose its fixed heading or the right-aligned Full history action. | ☐ Pass ☐ Issue ☐ N/A |
| Review Upcoming income & bills | Active recurring income and bills appear in the appropriate section with their due status. | ☐ Pass ☐ Issue ☐ N/A |
| Create or view a pending transaction | A clear pending cue appears before the amount, and the pending-only route/filter makes it easy to find later. | ☐ Pass ☐ Issue ☐ N/A |
| Open a transaction from the ledger | A clean detail view opens with its full information and a **Modify entry** action. | ☐ Pass ☐ Issue ☐ N/A |

## 9. Release-only checks — do only when you are ready

These checks are intentionally separate from normal review because they either send a real message, affect a published service, or require a decision about data. They are not blockers for reviewing the app’s core functionality.

| Check | When to perform it | Expected result | Decision |
|---|---|---|---|
| Publish the app | After the core review passes | A stable hosted version becomes available for production-only checks. | ☐ Approve later |
| Test device reminder delivery | After publishing, on the target mobile device | The background reminder arrives around the configured time and creates the expected inbox record. | ☐ Approve later |
| Test verification email | Only when you want an actual email | A single verification message arrives after the deliberate action. | ☐ Approve later |
| Test password-reset email | Only when you want an actual email | A single password-reset message arrives after the deliberate action. | ☐ Approve later |
| Migrate browser-only prototype records | Only if those records contain information worth keeping | Existing local records are copied deliberately without duplicates. | ☐ Approve later ☐ Skip |
